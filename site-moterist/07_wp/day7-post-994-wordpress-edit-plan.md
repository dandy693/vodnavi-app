# Day 7 Post 994 WordPress Edit Plan

## Objective

post_id 994 を、FANZA安全な使い方・不安解消記事として安全寄りに更新する前の手順を整理する。

本ファイル作成時点では、本番反映はまだ行わない。

## 編集画面URL

- `https://moterist.com/wp-admin/post.php?post=994&action=edit`

## 変更前確認

- post_id が `994` であることを確認する
- URL が `https://moterist.com/fanza_otoku250114/` であることを確認する
- 現タイトル、本文、ステータス、カテゴリー、タグ、メタディスクリプションを確認する
- ローカルバックアップ `07_wp/article-backups/post-994-before.md` があることを確認する
- 反映対象が `03_content/rewrites/post-994-final-rewrite.md` であることを確認する

## タイトル差し替え

- 現タイトルを控える
- `Proposed Title` をベースに新タイトルへ差し替える
- 「安全性確認」「支払い」「プライバシー」「退会前確認」の意図が伝わるか確認する
- 過度な煽りや保証表現が入っていないことを確認する

## 本文差し替え

- `Proposed Body` を貼り付ける
- 見出し階層が崩れていないか確認する
- リスク語 `未成年` `少女` `美少女` `女子高生` `JK` `ロリ` `高校` `中学生` `小学生` が残っていないか確認する
- `絶対安全` `完全にバレない` `必ず安心` `100%安心` などの保証表現が残っていないか確認する
- 支払い方法、請求・明細表示、退会・解約、問い合わせ、購入形式、プライバシー関連、年齢確認が公式確認前提の文言になっているか確認する

## メタディスクリプション差し替え

- 現行メタディスクリプションの有無を確認する
- `Proposed Meta Description` を反映する
- 安全性やプライバシーを断定していないか確認する

## カテゴリー確認

- 現在のカテゴリーを確認する
- `お役立ち情報` を維持する前提で確認する
- 追加カテゴリーがある場合は、不安解消記事として適切か見直す

## タグ確認

- 現在タグの有無を確認する
- 新規タグは作成しない
- 判断できない場合は現状維持とする

## noindex判断

- 本リライト案では noindex 前提ではない
- ただし、公開前確認で重大な表現リスクや事実誤認が残る場合は、人間判断で一時保留を検討する
- 実施有無と理由は `operation-log.md` に記録する

## 内部リンク確認

- 1095 へのリンク文言が「初心者向けガイド」になっているか確認する
- 1106 へのリンク文言が「入会メリット確認」になっているか確認する
- 954 へのリンク文言が「開催中セール確認」になっているか確認する
- リンク先slugやURLを人間が最終確認する

## CTA確認

- 主CTAが `FANZA公式で利用前の最新情報を確認する` になっているか確認する
- CTAが押し売りや不安あおりになっていないか確認する
- アフィリエイトリンク先が意図した遷移先か確認する

## PR/広告表記確認

- 記事冒頭またはCTA前でアフィリエイトリンクを含む旨が明示されているか確認する
- 誤認を招く表現や過度な販促文言になっていないか確認する

## 更新前チェック

- タイトル、本文、メタにリスク語が残っていない
- 支払い方法、請求・明細表示、退会・解約、問い合わせ、購入形式、プライバシー関連、年齢確認が断定表現になっていない
- カテゴリーとタグが意図どおり
- NoIndex が未チェックのまま
- 内部リンクとCTAが正しい
- 下書きテキストと実入力内容に差分がない

## 更新後公開画面チェック

- 公開URLでタイトルが反映されている
- 本文とCTAが意図どおり表示される
- メタディスクリプションが反映されている
- 内部リンクが正しく開く
- 不自然な改行、装飾崩れ、不要なHTMLがない

## ロールバック手順

1. `07_wp/article-backups/post-994-before.md` から変更前タイトルと本文を確認する
2. 変更前タイトルへ戻す
3. 変更前本文へ戻す
4. メタディスクリプションを変更前状態へ戻す
5. カテゴリー、タグ、NoIndex設定に変更があれば元へ戻す
6. `operation-log.md` にロールバック理由と確認結果を記録する

## operation-log.mdに記録する内容

- 実施日時
- 対象 post_id
- 対象URL
- 変更前バックアップの有無
- 変更したタイトル、本文、メタの概要
- カテゴリー、タグ、NoIndex の変更有無
- 公開画面確認結果
- 問題の有無
- 次回作業
