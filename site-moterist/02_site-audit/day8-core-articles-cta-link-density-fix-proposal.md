# Day 8 Core Articles CTA Link Density Fix Proposal

## 目的

Day 8 の公開確認結果を踏まえ、`1106` `994` の末尾導線過密と、3記事共通の `FANZA公式で最新情報を確認する` 系 CTA 文言の整合について、WordPress本番を更新せずに修正方針案を整理する。

今回は設計と比較のみを行い、本番更新、noindex、削除、301リダイレクト、slug変更は行わない。

## 前提

- 1095 のクエリなしURLでは更新後本文と内部リンク反映を確認済み
- 3記事ともスマホ表示は概ね問題なし
- 3記事とも canonical は正常、`noindex` は確認されず、meta description も反映済み
- 過密感は本文中ではなく、主に `1106` と `994` の末尾リンク集で観測された
- 3記事共通の公式CTAは、`al.dmm.co.jp` ラッパー経由で `video.dmm.co.jp/av/list/?genre=5002...` 系ページへ遷移している

## 判断基準

- 読者が迷わないこと
- 主CTAと補助リンクの役割が分かれること
- 内部回遊を落としすぎないこと
- アフィリエイトCTAの文言と着地先がズレないこと
- スマホ表示で圧迫感が出ないこと

## 現状の問題点

### 1106

- 末尾 `次に確認したいページ` の直下に、公式確認CTA1本と関連記事3本が連続している
- 本文中にも 1095 / 994 / 954 相当の導線があり、末尾で同系統の選択肢が再度まとまって出る
- 読者視点では `まず公式を見るべきか` `関連記事へ回遊すべきか` の優先順位が見えにくい

### 994

- 末尾 `利用前の確認リンク` の直下に、公式確認CTA1本と関連記事3本が連続している
- `購入前に見ておきたい公式情報` の本文中にも関連導線があるため、末尾で重複感が出やすい
- 不安解消記事の終盤としては、確認先が多く、安心して次の一歩を選ぶより「候補が並びすぎる」印象になりやすい

### 3記事共通の公式CTA文言

- 文言は `FANZA公式で最新情報を確認する`、`FANZA公式で登録前の最新情報を確認する`、`FANZA公式で利用前の最新情報を確認する` と広め
- 一方で実際の着地先は、広い意味の公式トップではなく、`video.dmm.co.jp/av/list/?genre=5002...` 系の特定ページ
- 読者が `公式トップや総合案内へ行く` と期待すると、文言と着地先の粒度にズレがある

## 修正しない場合のリスク

- 1106 / 994 の末尾で、主CTAと補助リンクの優先度が並列に見え、読者が迷う
- スマホでは1画面内にリンク候補が集まりやすく、圧迫感や離脱の原因になる
- 記事の役割分担はできていても、終盤の導線で意図が薄まり、回遊とCVのどちらも中途半端になる
- 公式CTA文言と着地先の粒度差が残ると、クリック後の期待差で違和感が出る

## 修正する場合のリスク

- 導線を減らしすぎると、内部回遊の受け皿が弱くなる
- 公式CTA文言を狭めすぎると、将来の着地先変更時に再調整が必要になる
- 末尾構成を整理する際に、役割の近いリンクを削りすぎると、記事間の回遊ネットワークが痩せる
- 見た目の密度だけを下げると、必要な補助導線まで消してしまう恐れがある

## 1106 の末尾導線改善案

### 案A: 公式CTAを主導線、関連記事を2本に絞る

- `次に確認したいページ` には主CTA1本と関連記事2本だけ残す
- 候補:
  - 主CTA: 公式確認
  - 補助1: 1095 初心者向け
  - 補助2: 994 安全確認
- `fanzaotoku` への導線は末尾から外し、本文中のセール文脈に寄せる

利点:

- 主CTAと補助導線の役割が最も分かりやすい
- スマホ終盤の圧迫感を下げやすい

懸念:

- セールハブへの回遊が末尾からは弱くなる

### 案B: 4本維持のまま、見出し内で役割を分ける

- `次に確認したいページ` を2段構成にする
- 例:
  - まず公式で確認したい方
  - あわせて読みたい関連記事
- 公式CTA1本と関連記事3本をグルーピングして、視覚的に分ける

利点:

- リンク本数を落とさずに優先度を示せる

懸念:

- 本数自体は変わらないため、スマホ圧迫感の改善は限定的

### 案C: 公式CTAを残し、関連記事は1本だけにする

- 末尾には主CTA1本と、記事役割に最も近い補助リンク1本だけ残す
- 1106 なら 994 か 1095 のどちらかに絞る

利点:

- 最もシンプル

懸念:

- 内部回遊が落ちやすい
- 1106 の比較検討記事としてのハブ性が弱まる

## 994 の末尾導線改善案

### 案A: 公式CTAを主導線、関連記事を2本に絞る

- `利用前の確認リンク` には主CTA1本と関連記事2本だけ残す
- 候補:
  - 主CTA: 公式確認
  - 補助1: 1095 基本理解
  - 補助2: 1106 入会メリット
- `fanzaotoku` は本文中のセール文脈または別記事側に寄せる

利点:

- 不安解消記事の終わりとして、選択肢が整理される
- 読者が `まず確認` と `次に読む` を区別しやすい

懸念:

- セールハブ回遊は少し弱くなる

### 案B: 4本維持のまま、セクションラベルを明確化する

- 公式CTAを単独で見せ、その下に `関連記事` として3本を置く
- 見た目の役割分離を優先する

利点:

- 内部回遊を落としにくい

懸念:

- 1106 と同様、本数自体は残るため、スマホではまだ密に見える可能性がある

### 案C: 末尾の関連記事を 1095 / 1106 の2本に限定する

- 994 の役割は不安解消なので、回遊先を `基本理解` と `メリット確認` に限定する
- セールハブは末尾から外す

利点:

- 役割分担がきれい
- 終盤リンクの迷いが減る

懸念:

- お得情報へ進みたい読者の受け皿が減る

## FANZA公式CTA文言の改善案

### 方針

- `公式` は残す
- ただし、`最新情報` のような広い表現より、着地先が `AVカテゴリ起点の一覧・案内確認` であることに寄せる
- 煽りや断定を避け、`確認する` ベースに寄せる

### 改善案候補

#### 共通で使いやすい案

- `FANZA公式の対象ページで最新情報を確認する`
- `FANZA公式ページで対象カテゴリの案内を確認する`
- `FANZA公式ページで利用前の案内を確認する`

#### 1095 向け

- `FANZA公式ページで基本情報と対象カテゴリを確認する`
- `FANZA公式ページで最新の案内を確認する`

#### 1106 向け

- `FANZA公式ページで登録前の案内を確認する`
- `FANZA公式ページで利用条件と対象カテゴリを確認する`

#### 994 向け

- `FANZA公式ページで利用前の案内を確認する`
- `FANZA公式ページで対象サービスの案内を確認する`

### 避けたい文言

- `FANZA公式トップで確認する`
- `FANZA公式サイトで全部確認する`
- `FANZA公式で最新情報を今すぐ確認する`

理由:

- 実際の着地先粒度とズレやすい
- 煽りが強く見える
- 案内範囲を広く言いすぎる

## 推奨案

### 推奨構成

- 1106: 末尾は `案A`
- 994: 末尾は `案A`
- 共通CTA文言: 記事文脈に応じて `FANZA公式ページで〇〇を確認する` へ寄せる

### 推奨理由

- 本数自体を減らすほうが、スマホ圧迫感の改善効果が明確
- 公式CTAを主導線、内部リンクを補助導線に分けやすい
- 1106 / 994 は本文中にも回遊導線があるため、末尾で3本すべてを維持しなくても回遊低下は限定的と考えられる
- CTA文言を `公式ページ` `対象カテゴリ` `登録前` `利用前` などに寄せると、着地先との粒度差を抑えやすい

## 本番反映する場合の最小変更案

### 1106

- `次に確認したいページ` から `開催中のセール・キャンペーン情報を確認する` を外す
- 公式CTA文言を `FANZA公式ページで登録前の案内を確認する` に寄せる
- 1095 / 994 への関連記事2本は維持する

### 994

- `利用前の確認リンク` から `開催中のセール・キャンペーン情報を確認する` を外す
- 公式CTA文言を `FANZA公式ページで利用前の案内を確認する` に寄せる
- 1095 / 1106 への関連記事2本は維持する

### 1095

- 末尾導線は現状維持でもよい
- 共通CTA文言だけ `FANZA公式ページで基本情報を確認する` などに寄せる余地がある

## 反映前に人間が確認すべき項目

- 1106 / 994 の末尾から 1 本減らしても、内部回遊の意図が維持されるか
- セールハブへの導線を末尾から外す場合、本文内や別記事側で十分に補えているか
- 公式CTAの実際の着地先が今後も同系統ページで維持されるか
- `FANZA公式ページで〇〇を確認する` という文言が、着地先ページの内容とズレないか
- スマホ表示で、CTAと関連記事が1画面に詰まりすぎなくなるか
- 変更後も、1095 / 1106 / 994 の役割分担が崩れないか

## 備考

- 今回はローカル設計のみ
- WordPress本番更新、noindex、削除、301リダイレクト、slug変更は行わない
- 本番反映する場合は、文言差し替えと末尾リンク本数調整だけに絞るのが安全
