# Day 8 Core Articles Mobile CTA Cache Check Plan

## 目的

Day 7で更新済みの `1095` `1106` `994` について、Day 8では公開画面の人間確認に絞って、スマホ表示、CTA遷移先、内部リンクの見え方、キャッシュ反映状況、meta description の反映確認項目を整理する。

今回はローカル設計フェーズであり、WordPress本番への更新、noindex設定、削除、301リダイレクト、slug変更は行わない。

## 対象URL

- 1095: `https://moterist.com/fanza20250329/`
- 1106: `https://moterist.com/fanza20250331/`
- 994: `https://moterist.com/fanza_otoku250114/`

## 前提整理

- 1095 / 1106 / 994 の本文更新と相互内部リンク追加は Day 7 で完了済み
- 1095 は `?v=20260504-1` 付きURLでは更新反映を確認済みだが、クエリなしURLでは旧キャッシュ残りの可能性が記録されている
- 1106 はクエリ付きURLとクエリなしURLの両方で更新内容確認済み
- 994 はクエリなしURLで更新内容確認済み
- Day 8では「見え方」「リンク先」「反映状態」を確認し、追加修正が必要かどうかを判定する

## 確認のゴール

- 1095 のクエリなしURLで、追加した内部リンクが本文上に見えている
- 3記事ともスマホ表示で、見出し、CTA、内部リンクの距離感が不自然でない
- 3記事の主要CTAが意図した遷移先へ進む
- 1106 / 994 の導線が過密でなく、CTAと内部リンクが競合していない
- meta description の反映確認で見るべき項目が揃っている

## 事前準備

- スマホ実機、またはブラウザのモバイルエミュレーションを使う
- キャッシュ確認用に通常表示とシークレット表示の両方を使う
- 1095 はクエリなしURLと、既知の確認用URL `?v=20260504-1` の差分を比較できるようにする
- 記録先として確認メモを用意し、記事ごとに `OK / 要確認 / 要再確認` を残す

## 確認順序

1. 1095 のクエリなしURLでキャッシュ反映と内部リンク表示を確認する
2. 1095 のスマホ表示とCTA遷移先を確認する
3. 1106 のスマホ表示、CTA遷移先、導線密度を確認する
4. 994 のスマホ表示、CTA遷移先、導線密度を確認する
5. 3記事共通で meta description の反映確認項目を点検する
6. 要修正箇所があれば、即更新ではなくローカルメモ化して次アクションへ送る

## 記事別チェック観点

### 1095

- クエリなしURL `https://moterist.com/fanza20250329/` で新本文が表示されるか
- Day 7で追加した `1106` と `994` への内部リンク文が本文内に見えるか
- 見出し直下、本文中、CTA周辺の余白が詰まりすぎていないか
- CTA直前直後に内部リンクが密集していないか
- 初心者向け入口記事として、本文の流れが `基本理解 → 詳細確認 → 不安解消` になっているか

### 1106

- `1095` から来た読者向けの比較検討記事として自然に読めるか
- CTAの前後に内部リンクが重なり、押し先が散っていないか
- `1095` と `994` への内部リンクが「補足導線」として見え、主CTAを食っていないか
- 見出し、本文、ボタンの間隔がスマホで窮屈に見えないか

### 994

- 不安解消記事として、CTAより先に確認ポイントが読みやすく並んでいるか
- `1095` と `1106` への内部リンクが多すぎず、安心確認導線として自然か
- CTA、内部リンク、関連記事表示が1画面内で過密になっていないか
- スマホでの段落区切りや箇条書きが詰まっていないか

## CTA遷移先の確認方法

- 各記事の主要CTAを上から順に確認する
- リンク押下前に、ボタン文言とその直前文脈が一致しているかを見る
- 遷移後のURL、遷移先ページ種別、訴求内容がボタン文言と一致するかを見る
- アフィリエイトURLの場合も、最終的にユーザーが到達するページ種別が意図どおりかを確認する

## CTA遷移先の判定基準

- `確認する` 系CTAなら、公式トップや該当カテゴリ、案内ページなど「確認可能なページ」に着地する
- `メリット` `安全` `登録前` など文脈付き内部リンクなら、その説明に対応する記事へ飛ぶ
- 同じ段落内に複数の強いCTAが並び、どれを押せばよいか迷う状態は `要再確認`
- リンク切れ、想定外ページ、成人導線のズレ、セール文脈との不一致は `要修正メモ`

## スマホ表示の確認ポイント

- H2 / H3 の直前直後余白が十分にあるか
- CTAボタンの上下に最低1段落ぶんの呼吸があるか
- 本文内内部リンクが連続しすぎていないか
- 関連記事やテーマ標準のリンク表示と本文内リンクが競合していないか
- ファーストビュー直後からリンクだらけに見えないか
- 1画面内に `CTA + 内部リンク + 関連記事導線` が重なりすぎていないか

## 1106 / 994 の導線過密判定

- 1つの見出しブロック内で、主CTAと補助内部リンクが並列になりすぎていないか
- CTAの直前直後に別記事リンクが続き、CV導線が弱まっていないか
- スクロール中に `次の行動候補` が3つ以上同密度で見える箇所はないか
- 「読む」「比較する」「不安を解消する」の役割が混線していないか

## 1095 のキャッシュ反映確認手順

1. クエリなしURLを通常表示で開く
2. タイトル、内部リンク文、meta description 抜粋候補を Day 7 の更新後内容と照合する
3. 旧表示の疑いがあれば、シークレット表示でも同URLを開く
4. まだ差分があれば `?v=20260504-1` 付きURLと比較する
5. クエリ付きだけ新表示、クエリなしは旧表示なら `キャッシュ未反映の疑い` と記録する
6. クエリなしでも内部リンク文が確認できれば `反映OK` とする

## Meta Description 反映確認で見るべき項目

- ページソース、SEOプラグイン出力、検索結果プレビューのどこで確認したか
- `meta name="description"` の有無
- description の文面が Day 7 更新後の意図と一致しているか
- タイトルと description の役割が重複しすぎていないか
- 古い文面が残っていないか
- canonical や robots に意図しない変更がないか
- 検索結果表示は即時反映でない前提を置き、まずHTML出力時点の反映有無を確認する
