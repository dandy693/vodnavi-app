# Day 8 Core Articles Mobile CTA Cache Check Summary

## 要約

Day 8では、Day 7で更新済みの `1095` `1106` `994` に対して、公開画面の最終人間確認を行う。

今回の主目的は更新作業ではなく、以下5点の確認計画を固定することにある。

- 1095 のクエリなしURLで内部リンクと更新本文が見えるか
- 3記事のスマホ表示で見出し、CTA、内部リンクの距離感が自然か
- 主要CTAの遷移先が文脈どおりか
- 1106 / 994 の導線が過密になっていないか
- meta description の反映確認で何を見るべきか

## 記事ごとの重点

- 1095 はキャッシュ反映確認が最優先。クエリ付きURLでは確認済みのため、クエリなしURLとの差分確認が必要
- 1106 は比較検討記事として、主CTAと補助内部リンクの競合有無を重点確認する
- 994 は不安解消記事として、安心材料より先にリンクが密集していないかを重点確認する

## 判定方針

- 追加修正が必要そうな箇所が見つかっても、このフェーズでは本番更新しない
- その場で直すのではなく、`要再確認` `要修正メモ` `反映OK` の形で残す
- meta description は検索結果の表示文ではなく、まずHTML出力上の反映を基準に確認する

## 次アクション

- 実機またはモバイルエミュレーションで 1095 → 1106 → 994 の順に確認する
- 1095 はクエリなしURLと `?v=20260504-1` の両方を比較する
- 3記事のCTA遷移先と導線密度を記録し、必要なら次工程で修正候補を整理する
