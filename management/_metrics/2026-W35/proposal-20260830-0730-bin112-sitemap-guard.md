# 起案 — 全損 sitemap を静かに配信しないためのガード（**1案・実装は 9/12 以降の裁定待ち**）

**起案日**: 2026-08-30（第112便 タスクC）
**状態**: **起案のみ。本便では実装していない。**
**根拠**: `FACT_GOVERNANCE` §22（2026-08-28 18:26 JST の生成で本体 sitemap が 17 URL まで縮んだ実測）

> **【厳守】本書は案である。CTO は採否を決定しない。**

---

## 1. 防ぐ事象

**`buildSitemapEntries()` は、FANZA API が全フロアで失敗しても例外を投げず、`works` / `genres` / `actresses` が 0 件のまま「成功」として return する。**
**呼び出し側（`src/app/sitemap.xml/route.ts`）はその結果をそのまま XML にして 200 で配信する。**
**→ 全損が「正常なレスポンス」として配信され、キャッシュに載って固定される。**

**実測（2026-08-30）**: 本体 sitemap は **17 URL**（静的9 + articles 8）。**works 3,948 → 0。** **`cohort-1`（5,000）と `archive`（3,020）は健在**——**両者は別ルートで生成されており、本体だけが落ちた。**

---

## 2. 案（**1案のみ・指示どおり**）

### 前回値を維持する（**フェイルクローズではなくフェイルフリーズ**）

**`works` の件数が閾値未満なら、新しい結果を捨てて前回の sitemap をそのまま配信する。**

| 要素 | 内容 |
|---|---|
| **判定** | `works.length < MIN_WORKS`（初期値の目安 **500**。**現行は約 3,948 で、4フロア × 4ページ × 100件 の上限は 1,600**——実際の値は重複除去と鏡像フロア除外の後の数） |
| **閾値未満のときの動作** | **前回の生成結果（Supabase または Vercel KV 等に保存した直近の成功分）を返す。** **新しい結果で上書きしない。** |
| **ログ** | **`VODNAVI_SITEMAP_DEGRADED` タグで `works` / `genres` / `actresses` / `floors_ok` / `floors_failed` を1行出す**（既存の `VODNAVI_*` 慣例に合わせる） |
| **保存先** | **`sitemap_archive` と同じ Supabase を使うのが自然**（既に `persistSitemapWorksArchive` が同テーブル系に書いている＝新しい依存を増やさない） |

### なぜ「ビルドを失敗させる」を採らないか

- **sitemap はビルド時ではなくランタイム（route handler / `revalidate`）で生成される。** **ビルドを失敗させても、ランタイムの再生成には効かない。**
- **例外を投げて 500 を返す案**は、**Google に 500 を見せることになる**。**古い内容を返すほうが、検索エンジンにとって害が小さい**（sitemap は「最新であること」より「壊れていないこと」が重要）。

---

## 3. 【厳守】この案が解決しないこと

- **「前回値」が既に全損している場合は救えない。** **初回導入時に、健全な値が保存されていることを確認する必要がある。**
- **本体 sitemap が 8/28 18:26 以降 一度も再生成されなかった原因**（`revalidate = 3600` が着地せず、クエリを変えても `X-Vercel-Cache: HIT` が続いた）**には触れない。** **これは別の問題であり、§16-5(2) の「`revalidate` 宣言が着地しない」と同型の可能性がある。** **本案は「壊れた値を配信しない」だけで、「再生成が起きない」は直さない。**
- **検知はするが通知はしない。** **`VODNAVI_SITEMAP_DEGRADED` を誰が見るかは別途決める必要がある。** **§13-6-1 の裁定（検知を増やしても事故は防げない）を踏まえ、通知先ではなく__誰の作業手順に載せるか__を決めること。**

---

## 4. 判断が必要な点

1. **採否**
2. **`MIN_WORKS` の値**（**平常時の件数分布を測っていない。§13-8-1 と同じく、まず測定ログだけを先に入れる選択もある**）
3. **前回値の保存先**（Supabase / Vercel KV / 他）
4. **実装時期**（9/12 以降のどこか）
