| 指示の分岐 | 実態 |

| 前日側に **14:00 の部分データ混入あり** → 汚染の可能性を明記し確定扱いにしない | **該当しない**（14:00 分は部分データではない） |

### **8/25 に付すラベル（確定）**

> **前日（8/24）の最終スナップショットは 14:00 分（404行）。**
> **4フロアすべて存在・`failedFloors` 空・16コールすべて stale-serve で救済・全行が同一の `campaign_end`・`found=rows=saved=404` であることから、__部分データではない__。**

> **→ 比較基準の汚染は認められない。新規検知・消滅検知は__通常どおり扱ってよい__。**

- **【厳守】上のラベルを省略しないこと。** **「正常だったから何も書かない」とすると、後から「8/24 は API が止まっていたのに検知結果をそのまま使ったのか」という疑いを晴らせなくなる。**

3. **8/25 06:00 のバッチが API 停止中に走った場合**、`ok` / `okFloors` / `failedFloors` / `STALE_SERVED` の有無を同じ5点で確認すること。**キャッシュの鮮度上限（一覧48時間）を超えていれば stale-serve は効かず、`failedFloors` に現れる。**
