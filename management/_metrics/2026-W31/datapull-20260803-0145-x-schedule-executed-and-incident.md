## 3. 原因調査

### 3-1. Airtable Automations（閲覧のみ・有効無効の切替なし）

base `app0VKGU2B16qny6c` のオートメーションは **1本のみ**。

| 項目 | 内容 |
|---|---|
| ID / 名称 | `wflUyeGut6FflwgJu`「エラー通知」 |
| 状態 | `deployed` |
| トリガ | `recordMatchesConditions` — `posts` テーブルで **ステータス = エラー**（`selJi6042aByaPcfG`）に一致したとき |
| アクション | `sendEmail` **1ノードのみ**（`wacJyAyHmrDvoFScx`） |

→ **フィールドを更新するアクションは存在しない**。オートメーションは本事象の原因ではない。

### 3-2. フィールド設定

| フィールド | 型 | config（API 実測） |
|---|---|---|
| ステータス `fldiGogHs9F7w5t2q` | singleSelect | `choices` のみ（ストック / 承認済 / 投稿済 / エラー）。**既定値の設定は返却されない＝既定値なし** |
| 予約日時 `fldDrNzqVRb9LxxqD` | dateTime | `dateFormat: iso` / `timeFormat: 24hour` / **`timeZone: Asia/Tokyo`**。**空欄時の挙動に関する設定項目は存在しない** |

→ 実証として、01:14:01 の API 作成直後の照会では 14 件すべて「ストック」であった（既定値による上書きは起きていない）。

### 3-3. Revision history（**決定的**）

Airtable は変更経路を区別して記録する。**CTO（Claude）の書き込みは必ず
「You edited via API (using Airtable for Claude integration)」**と記録される。

### 3-4. 判明した事実

- 両レコードの **ストック→承認済 は「You edited this post」＝ Airtable UI（ブラウザ）からの編集**として記録されている。
  **「via API (using Airtable for Claude integration)」ではない**＝**CTO（Claude）の API 書き込みではない**
- 発生時刻は **≒ 01:23〜01:24 JST**。CTO のレコード作成（01:14:01）より後、CTO の13件更新（≒01:36）より**前**
- Airtable の帰属表示はいずれも同一アカウント（"You"）だが、**経路（UI / API 連携）は明確に区別されている**
- **誰の操作かというアカウント単位の identity は、この表示からは分離できない**（同一 Airtable アカウント配下）。したがって「UI 経由の操作であった」ことは確定、「操作主体が誰か」は**未確認**

### 3-5. 付随して確認できた仕様

- **revision history の保持期間は 2 週間**（画面表記「You have 2 weeks of revision history.」／"Upgrade to extend your history!" の案内あり）
- 「Changes made to data that is syncing in from outside Airtable are hidden.」の注記あり
- `History` メニューには `Undo` / `Redo` / `Snapshots` / `Record revision history` / `Trash` があるが、**いずれも実行していない**（`Clear revision history`・`Undo`・`Delete post` は押していない）
