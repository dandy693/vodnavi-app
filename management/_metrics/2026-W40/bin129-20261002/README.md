## B4. 発売カレンダー vs ⑬値下がり・セール入り通知

| 観点 | 発売カレンダー | ⑬値下がり／セール入り |
|---|---|---|
| 既存データ | `sitemap_works_archive.released_at`（videoa の未来日付 **1,050 件**・2026-09-29） | `price_history` はセール中の rank 上位だけを記録＝**セール外の価格は 0 行**。値下がりは 31 日で 6 件 |
| 追加の書き込み | 不要（読み取りのみで組める） | 作品単位の値下がりには**記録母集団の拡張が必要**（本番 cron の書き込み対象変更・容量見積り） |
| 外部から参照されやすさ | **未検証**（どちらも当サイトで測っていない・§15-2 軸4） | 同左 |

**→ 既存データで安く作れるのは発売カレンダー。** 参照されやすさは比較材料が無いため判断に使っていない。

**設計の骨子（発売カレンダー）**
- 面: `/releases`（今日〜+30 日）と `/releases/{YYYY-MM}`。日付ごとに作品カードを並べ、カードは既存の works 詳細へ。
- データ: `sitemap_works_archive`（`released_at ≥ 今日`・`floor_code`）。表示に必要なタイトル・画像は `fanza_response_cache` の PK 照会、MISS 時は FANZA API `cid=`（E6① の 404/500 を流用）。
- self-canonical。クエリ付き URL を作らない（`?sort=` は使わない・§2）。
- **制約（明記）**: archive は「main sitemap の窓を通過した作品」だけ＝網羅していない（§18）。`released_at` が FANZA 側の発売日変更に追随するかは未確認。時点注記「2026 年○月○日時点」を出す。
- 工数: 2 日（ページ 2 種＋sitemap 追記）。
