## 2. CSO が実施する手順（画面遷移レベル）

**前提**: **`moterist.com@gmail.com` でログインしていること**（GA4 プロパティ `p489519780` の管理権限を持つアカウント。§3 / メモリの「GA4 既定プロパティの罠」に注意）。

### 手順1 — Google Cloud プロジェクトを作る

1. `https://console.cloud.google.com/` を開く
2. **右上のアカウントアイコンを確認**し、`moterist.com@gmail.com` になっているか見る。違えば切り替える
3. 画面**上部中央のプロジェクト選択ボタン**（「プロジェクトを選択」または既存のプロジェクト名）をクリック
4. ダイアログ右上の **「新しいプロジェクト」** をクリック
5. **プロジェクト名**に `vodnavi-ga4-reader` と入力（組織は「組織なし」のままでよい）→ **「作成」**
6. 作成完了の通知が出たら、**上部のプロジェクト選択ボタンから作ったプロジェクトを選ぶ**（**ここを選び忘れると、以降の操作が別プロジェクトに入ってしまう**）

### 手順2 — Google Analytics Data API を有効にする

1. 左上の**ハンバーガーメニュー（☰）** → **「APIとサービス」** → **「ライブラリ」**
2. 検索窓に **`Google Analytics Data API`** と入力
3. 検索結果の **「Google Analytics Data API」** をクリック
4. **「有効にする」** をクリック（すでに有効なら「管理」と表示される。その場合は何もしなくてよい）

### 手順3 — サービスアカウントを作る

1. ☰ → **「IAMと管理」** → **「サービス アカウント」**
2. 上部の **「+ サービス アカウントを作成」** をクリック
3. **サービス アカウント名**に `ga4-reader` と入力 → **「作成して続行」**
4. **「このサービス アカウントにプロジェクトへのアクセスを許可する」は空欄のまま「続行」**（**プロジェクト側の権限は不要**。GA4 側で権限を付けるため）
5. **「完了」** をクリック

### 手順4 — JSON キーを発行する（**取り扱い注意**）

1. サービスアカウントの一覧に `ga4-reader@....iam.gserviceaccount.com` が出るので**クリック**
2. 上部タブの **「キー」** をクリック
3. **「鍵を追加」** → **「新しい鍵を作成」**
4. **キーのタイプは「JSON」を選択** → **「作成」**
5. **JSON ファイルが自動でダウンロードされる**
6. **【重要】このファイルはパスワードと同じ扱いをすること。** メールやチャットに貼らない。**中身を CTO に送らない**（配置だけしてもらえれば CTO は読まずに使える）

### 手順5 — GA4 プロパティに閲覧権限を与える

1. `https://analytics.google.com/analytics/web/?authuser=1#/a355462253p489519780/admin` を開く
2. **プロパティ列**（右側）の **「プロパティのアクセス管理」** をクリック
   - ※ **アカウント列（左側）ではなくプロパティ列**。間違えると範囲が広くなりすぎる
3. 右上の **「＋」** → **「ユーザーを追加」**
4. **メールアドレス欄に、手順3で作ったサービスアカウントのアドレスを貼る**（`ga4-reader@<プロジェクトID>.iam.gserviceaccount.com`。手順4-1 の画面でコピーできる）
5. **「新規ユーザーにメールで通知する」のチェックを外す**（サービスアカウントは受信できない）
6. **役割は「閲覧者」を選ぶ**（**編集者・管理者は選ばない**。読み取りしか行わないため）
7. 右上の **「追加」**

### 手順6 — キーファイルを配置する（**2026-08-16 改訂: CSO はダウンロードするだけでよい**）

**【改訂の理由】`mv` はファイル内容を読み出さないため、CTO が中身を開かずに配置できる。** **CSO の作業を1手減らす。**

1. **ダウンロードしたファイルはそのまま `~/Downloads`（`C:\Users\Tachi\Downloads`）に置いておく。改名も移動も不要。**
2. **CTO に「ファイル名」だけを伝える。**（例: `vodnavi-ga4-reader-1a2b3c4d5e6f.json`）
   - **【重要】`~/Downloads` には既に `kit-net-5f0277ac68f0.json` という別プロジェクトの鍵らしきファイルがある**（更新 2026-07-26）。**取り違えを防ぐため、ファイル名は正確に伝えること。CTO は伝えられた名前と完全一致するファイルのみを扱う。**
3. **CTO が以下を実行する**（中身は開かない）:
   ```
   mv "/c/Users/Tachi/Downloads/<伝えられたファイル名>" \
      "/c/Users/Tachi/projects/VODNAVI-GROUP/app-concierge/ga4-service-account.json"
   ```
4. **【必須】宛先名は `ga4-service-account.json` に固定する。**
   - **理由**: **GCP がダウンロードする既定のファイル名は `<プロジェクトID>-<ハッシュ>.json` 形式で、`.gitignore` の3つの JSON パターン（`ga4-service-account.json` / `*credentials*.json` / `*service-account*.json`）のいずれにも一致しない。** **改名せずにリポジトリ配下へ置くと git の追跡対象になる。**
   - **改名した時点で `app-concierge/.gitignore:53` に一致する。**
5. **CTO が配置後に確認する**（下記 §6）。
6. **【CSO へ】ダウンロード時のファイル名を控えておくこと。** 手順4-5 の画面で自動命名されるため、**ブラウザのダウンロード通知に出る名前をそのままコピーするのが確実。**

**git 管理外であることの確認**: **`.gitignore` への追加は 第38便・第39便で完了済み**（`ga4-service-account.json` / `*.key` / `*credentials*.json` / `*service-account*.json`）。**追加作業は不要。** **ただし上記のとおり、GCP の既定ファイル名のままでは一致しないため、改名が必須である。**

## 4. 割当・課金

| **3** | **git 追跡対象外の確認** | `git status --short` / `git check-ignore -v app-concierge/ga4-service-account.json` | **`git status` に現れない。** `check-ignore` が **`.gitignore:53`** を指す |

**【厳守】どの段階でも鍵ファイルの中身を開かない。** **`cat` / `Read` / エディタでの表示をいずれも行わない。** **スクリプトは鍵を読み込むが内容を出力しない設計にしてある**（例外メッセージにも混ざらないよう `catch` で握り直している）。

- **手順4 で「鍵ファイルを読めない、または形式が不正」** → ファイルが壊れているか JSON でない。**中身は見ずに CSO へ再ダウンロードを依頼する。**

## 5. CTO 側の実装（資格情報の配置後）

- **スクリプト**: `app-concierge/scripts/ga4-pull.mjs`（新規）
- **方式**: サービスアカウント JSON で JWT を作り、`https://analyticsdata.googleapis.com/v1beta/properties/489519780:runReport` を叩く。**依存パッケージの追加は行わず、`node:crypto` で JWT を自作する**（既存の `x-post-generator.mjs` / `audit-posts.mjs` と同じく依存ゼロで動かす）。
- **出力**: `management/_metrics/<週>/ga4-<日時>-<内容>.md`
- **運用**: **木曜サイクルに統合**（`CLAUDE.md` の週次チェック）。
- **§10 の適用**: **取得後、合計と内訳が一致することを検算する**（例: 日別の合計 = 期間合計）。**一致しない場合は「一致しない」と書く。**
