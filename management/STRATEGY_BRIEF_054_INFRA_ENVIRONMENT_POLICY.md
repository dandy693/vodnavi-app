# STRATEGY BRIEF 054: Vercel環境変数スコープ完全同期における標準インフラポリシー

- **ステータス**: APPROVED (CSO 策定 / インフラ統括ポリシー)
- **策定日**: 2026-06-09
- **対象ドメイン**: *.vodnavi.jp (全 Vercel スコープ)
- **関連**: `STRATEGY_BRIEF_053_PREVIEW_ENV_SYNC.md`（本ポリシー策定の契機となった具体事象）

## 1. ポリシー策定の背景と目的

`app.vodnavi.jp` のプレビュー環境構築時において、FANZA API 認証情報のスコープ漏れに起因するシステム警告が発生した。今後予定されているアフィリエイト ASP（DMM TV、U-NEXT 等）の拡張時において、同様の開発環境フェイルを自動的に抑止し、インフラ運用の手作業を削減するための鉄則を定義する。

## 2. 標準インフラポリシー（遵守ルール）

1. **全スコープ強制バインドの原則**:
   - WebAPI の認証トークン、アフィリエイト ID、およびそれに準ずる**サーバー側 fetch 用**環境変数（`DMM_API_ID`, `DMM_AFFILIATE_ID` 等）を Vercel / 各種ホスティング環境に新規登録・更新する際は、必ず `Production`, `Preview`, `Development` の**すべてのスコープを有効化**しなければならない。
2. **本番/開発環境のアイソレーション（分離）**:
   - セキュリティ上の理由で検証用アカウントを分離する必要がある場合に限り、同一の変数名に対してスコープごとに異なる「値（Value）」を設定することを許可する。値が未設定のままスコープから除外するオペレーションは原則禁止とする（§2.4 例外を除く）。
3. **新規 ASP 追加時のチェックリスト自動組み込み**:
   - 今後メディア側（`vodnavi.jp`）および成約アプリ側（`app.vodnavi.jp`）に新しいマネタイズ API を追加する開発ランブックを作成する場合、必ず「プレビュー環境への変数同期確認」の項目を必須チェックゲートとして設けること。
4. **例外：計測タグ・プレビュー隔離変数（カーブアウト）** ※2026-06-09 CTO 技術補遺:
   - `NEXT_PUBLIC_GA_MEASUREMENT_ID` / `NEXT_PUBLIC_GTM_ID` 等の**計測タグ系**変数は本原則の対象外。理由: 当該タグは `NODE_ENV !== "production" → null` の dual guard で Preview デプロイには元から inject されない設計であり、加えて CPU 防衛（PR #1）で Preview host は `noindex` / `Disallow:/` に隔離されている（TASK_BOARD CTO-Deploy-Log 2026-06-02 / ALERTS 2026-05-26 CPU 防衛エントリ）。これらを Preview スコープへ強制バインドしても無効（guard が runtime で遮断）かつ team の既存運用（「Preview scope は機能影響なしで skip」）と整合しないため、**全スコープ強制の対象は §2.1 のサーバー側 fetch 用変数に限定**する。

## 3. 次世代拡張への備え

本ポリシーの確定により、将来的な DMM TV / U-NEXT 等の ASP 拡張時においても、サーバー側 fetch 用変数のスコープ漏れによる開発ブランチのステージング fail を構造的に抑止する。計測タグの Preview 隔離（§2.4）は維持され、本番計測の純度と Preview の SEO 隔離は両立する。
