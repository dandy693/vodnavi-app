## 3. 束2: リプ案生成ツール（基盤Aの中核）

**目的**: 対象投稿の本文を貼ると、作品知識に基づく非宣伝リプ案を3種返す。HUMANは選んで投稿するだけ。

**CTO作業**
- Claude Code のスキル（またはローカルスクリプト）として実装。入力: 対象投稿本文、対象handle（x_targets参照）、任意で作品ID。出力: 3案（A=共感・一言、B=作品知識の補足、C=質問で返す）。各80〜140字。
- 作品知識はSupabase（vodnavi-production）の既存worksデータから引く。FANZA APIの新規呼び出しは増やさない。
- **ガードレール（生成側で強制）**:
  - URL・ドメイン・af_id・「vodnavi」の文字列を含まない（既定則: リプにリンク禁止）。
  - 宣伝文言（「詳しくはこちら」「チェック」等の誘導）を含まない。
  - 女優本人への言及は敬称付き・容姿への言及なし・作品内容の露骨な描写なし。
  - 出力後に正規表現で URL/@/af_id を再検査し、違反案は破棄して再生成。
- 実績は `x_replies` に記録できるようCLIから1行追記できる導線を付ける。
- 許可範囲: リポジトリ内 `tools/` 配下の新規ファイルと、Supabaseへの読み取りのみ。

**HUMAN日次ルーチン（30分・平日）**
- リプ 10〜20件（台帳「本日の対象」から）。リンクなし。
- フォロー 20〜30件（対象アカウントの投稿に反応しているユーザー中心）。自己設定上限は8→30に改定。フォロー/フォロワー比が2倍を超えたら一旦止める。
- 引用ポスト 1〜2件（女優・メーカー公式の発売告知に「この作品は〇〇系」の一言＋作品ページ）。引用にはリンクを入れてよいが、直リンク1日1件枠とは別枠で、app.vodnavi.jp のworks詳細ページに限る。
- 既定則の再掲: リプにリンクを一切含めない／直接アフィリエイトリンク投稿は1日1件／#PR必須／同時申込は勧めない。

## 4. 束3: 反応型投稿テンプレート（基盤C）

**目的**: 投稿の大半を「リンク前提」から「反応前提」に転換。リンクは1日1件枠＋固定ポスト＋bioに集約。

**CTO作業**
- 既存パイプライン（FANZA API → 生成 → Airtable posts → Make シナリオ5615632）に `post_type` を追加。型は5種:
  1. `countdown`: 発売日カウントダウン（予約新作・単価2,000円台を優先。根拠: クリック加重中央値2,180円、最大成果は発売当日購入）
  2. `weekly5`: 「今週の新作5本」（束4の1枚画像に紐づく）
  3. `poll`: アンケート（「どっちを買う？」2択）。Make側でX投票APIに対応しているか要確認。非対応なら本文で「①②で返信」形式に落とす。
  4. `quiz`: 女優クイズ（作品情報から出題・答えは翌日の投稿）
  5. `ranking`: 価格帯別／ジャンル別ランキング（Supabaseの既存データで生成）
- 日次配分（現行 20:45〜24:00・900秒間隔の枠内）: 反応型4〜5件＋直リンク（T1改）1件。時間帯・間隔は変更しない（変数分離）。
- 各投稿に `utm_content=post_type名` を付与し、GA4で型別に分離できるようにする。
- 生成プロンプトには時点注記のルール、円表記、クーポン非記載、#PR（リンク付き投稿のみ）を組み込む。
- 許可範囲: postsテーブルへのフィールド追加、生成スクリプト、Makeシナリオは **テキスト投稿の範囲でロジック変更が不要なら触らない**。画像添付が必要な場合は束4で別途見積もり。
