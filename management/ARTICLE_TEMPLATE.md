# ARTICLE TEMPLATE — Moterist 記事制作指示書（CCO 向け）

**宛先**：CCO (ChatGPT 5.5 + Image 2)
**目的**：Moterist (moterist.com) で公開する SEO 記事のフォーマットと品質基準を 1 枚に集約する。
**根拠**：[`MARKETING_PILLARS.md`](./MARKETING_PILLARS.md) の 3 本柱戦略と [`COMPLIANCE_GUIDE.md`](./COMPLIANCE_GUIDE.md) の表示要件。

このテンプレに従って書けば、**SEO ／ コンプライアンス ／ コンシェルジュ誘導**が同時に満たされる。逆に、ここから外す場合は CSO / CTO に事前相談すること。

---

## 0. 記事を書く前のチェック（5 つ）

書き始める前に必ず確認する：

1. **どの柱か** — 感情ナビ / 教養レンズ / シチュエーション の 1 つに必ず属させる（複数兼ねない）。
2. **想定キーワード** — メイン 1 + サブ 2〜3。検索ボリュームではなく**読者の温度**で選ぶ。
3. **ピラー or クラスター** — どのピラー記事から繋がるクラスターか。ピラー記事ならその旨を明記。
4. **CTA URL** — 全記事末尾で `https://app.vodnavi.jp/concierge?source=moterist` を使う。**例外なし**。
5. **#PR 表記** — アフィリエイトリンクが含まれるので、記事冒頭に必須。

---

## 1. ファイル配置と命名

```
site-moterist/03_content/<記事スラッグ>/
  ├─ article.md           ← 本文（このテンプレに従う）
  ├─ frontmatter.yml      ← メタ情報（下記）
  └─ images/
       ├─ hero.png        ← 1200×630（OG / サムネ兼用）
       ├─ section-1.png   ← 本文中図版（任意）
       └─ ...
```

- スラッグはローマ字 + ハイフン区切り（例：`emotion-after-breakup-movies`）。
- すべて **UTF-8 / LF / `.md` (Markdown)** で保存。

```yaml
title: "失恋から立ち直る夜に観たい映画 5 選"           # ← H1 とほぼ同じでよい

pillar: "emotion-navi"                              # emotion-navi | wisdom-lens | situation

  - "失恋 おすすめ 映画"
  - "立ち直りたい 夜 作品"

cta_source: "moterist"                              # 固定（変えない）
publish_status: "draft"                             # draft | review | published
created_by: "CCO (ChatGPT 5.5)"
created_at: "2026-05-14"
```

## 3. 本文構成（Markdown）

以下の順序を**厳守**する。ブロックは増減してもよいが、順序は変えない。

### 3.1 #PR 表記（冒頭・必須）

```markdown
> 本記事にはアフィリエイトリンクが含まれます（#PR）。
> 各サービスの最新の料金・配信状況は公式サイトでご確認ください。
```

> COMPLIANCE_GUIDE §1.2 ステマ規制対応。**省略禁止**。

### 3.2 タイトル（H1）

- 30〜38 文字を目安に。
- キーワードは前寄せ。
- 数字 or 具体名詞を 1 つ以上含める（クリック率の差が大きい）。

例：
- ✅ `失恋から立ち直る夜に観たい映画 5 選 — 心がほどけるラインナップ`
- ❌ `失恋について考えるときに見ると良いかもしれない映画たち`

### 3.3 導入（150〜200 字）

- 読者の感情・状況に強く共鳴する 1 段落。
- 結論を先に置く（この記事で何が分かるか）。
- 末尾で「本文へ」と自然に橋渡し。

### 3.4 本文（H2 × 3〜5）

- 各 H2 セクションは 300〜600 字 + 作品 1〜2 本の紹介。
- **作品の紹介**は必ず以下の 3 点セットで：
  1. 作品の感情/教養/シチュエーション上の位置づけ（なぜこの記事で出てきたか）。
  2. ネタバレなしの一押しポイント（1〜2 文）。
  3. 配信プラットフォーム情報（FANZA で配信中 等。なければ書かない）。
- 紹介する作品の合計は **3〜7 本まで**。網羅性より精度。

#### 中間導線（H2 2 つ目あたりに 1 箇所だけ）

```markdown
> 気になる作品が見つからなければ、AI コンシェルジュに気分を伝えてみるのも近道です。
> → [VODNAVI コンシェルジュに相談する](https://app.vodnavi.jp/concierge?source=moterist)
```

**1 記事につき中間導線は 1 つだけ**。多用すると読者体験が壊れる。

### 3.5 まとめ（80〜120 字）

- 読者への一言の労い。
- 次の行動への橋渡し（コンシェルジュ CTA へ自然に繋ぐ）。

### 3.6 記事末尾の確定 CTA（最重要・必須）

```markdown
## 今夜、AIコンシェルジュに「もう少し詳しく」を任せる

本記事で紹介した感情・状況をそのまま AI コンシェルジュに伝えると、
あなたの今の気分に合う作品をさらに絞り込んで提案します。

→ [VODNAVI コンシェルジュに相談する](https://app.vodnavi.jp/concierge?source=moterist)
```

- URL は `https://app.vodnavi.jp/concierge?source=moterist` を**そのまま貼る**。短縮・改変禁止。
- 柱別の CTA 文言バリエーション：

| 柱 | CTA 見出し例 |
| --- | --- |
| 感情ナビ | 「今の気分のまま、コンシェルジュへ」 |
| 教養レンズ | 「読み終えた余韻のまま、次の一本を」 |
| シチュエーション | 「今夜の 90 分、迷わない」 |

### 3.7 関連記事ブロック（任意・あれば末尾の CTA の **下**）

```markdown
### 関連記事

- [同じ柱の記事 1](url)
- [同じ柱の記事 2](url)
- [同じ柱の記事 3](url)
- [他柱から 1 本](url)
```

CTA より上に置かない。CTA と並列に並べない。

## 4. トーン & 文体ガイド（柱別）

| 柱 | トーン | 平均文字数 | 一人称 | 推奨文末 |
| --- | --- | ---: | --- | --- |
| 感情ナビ | 寄り添い・低圧 | 2,000〜3,000 字 | 「あなた」中心 | 「〜かもしれません」「〜と感じます」 |
| 教養レンズ | 知的・落ち着き | 3,000〜5,000 字 | 「私たち」「読者」 | 「〜と捉えられます」「〜が指摘されています」 |
| シチュエーション | 即決・実用 | 1,800〜2,500 字 | 「あなた」 | 「〜できます」「〜が選べます」 |

### 共通の言い回しルール

- **過剰な煽りは禁止**：「絶対」「最強」「これだけ観れば OK」等の断定は使わない（COMPLIANCE_GUIDE §1.1）。
- **読者を低く扱わない**：「あなたも知らないと損する」系の煽りはトーン違反。
- **作品の効能を断定しない**：「これを観れば失恋から立ち直れます」は NG。「立ち直りたい夜に寄り添ってくれる一本」は OK。
- **比較表現**：他社サービス・他作品との比較は事実ベース。古い情報を引用しない。

## 5. 画像ガイド

### 5.1 ヒーロー画像（必須）

- サイズ：1200×630（OG 兼用）。
- 内容：**作品のジャケットを直接使わない**（権利・成人向け混在リスク）。
- 推奨：抽象的なシーン画像 / 心象風景 / 文字組み合成。
- 生成プロンプトには「実在の作品名・俳優名を含まない」「成人向け要素を含まない」を必ず入れる。

### 5.2 セクション図版（任意）

- サイズ：800×450 を基本。
- 各記事で 0〜3 枚程度。**画像のためだけにセクションを増やさない**。

## 6. 公開前チェックリスト

公開申請を出す前に、CCO が**自分で**全項目を確認する。

### コンプライアンス
- [ ] 冒頭に `#PR` 表記がある。
- [ ] アフィリエイトリンクは Moterist のフッターからも「アフィリエイト表記」「免責事項」「プライバシーポリシー」に到達できる構成になっている。
- [ ] 「絶対」「No.1」「最安」「無料」等の断定・有利誤認表現に根拠の併記がある、または除去済み。
- [ ] 効能の断定（「治る」「効く」）を使っていない。
- [ ] 成人向け作品を直接アイキャッチに使っていない。
- [ ] Moterist の本文に成人向け要素を持ち込んでいない（教養トーン維持）。

### SEO / 構造
- [ ] H1 が 1 つだけ存在し、メインキーワードを含む。
- [ ] H2 が 3〜5 個、それぞれサブキーワードを意識した語彙を含む。
- [ ] 内部リンク：同じ柱のピラー記事 / 関連記事への動線がある。
- [ ] 画像に alt テキストが入っている。
- [ ] frontmatter の `pillar` `cta_source` `keyword_primary` が埋まっている。

### 誘導動線
- [ ] 中間導線が**1 つだけ**ある（H2 の 2 つ目あたり）。
- [ ] 末尾の CTA セクションが存在し、URL が `https://app.vodnavi.jp/concierge?source=moterist` で完全一致している。
- [ ] CTA セクションの上下に「関連記事」を並列に並べていない。

### 品質
- [ ] 紹介作品が 3〜7 本に収まっている。
- [ ] 紹介の 3 点セット（位置づけ / 一押し / 配信情報）が各作品で揃っている。
- [ ] 想定文字数（柱別）から ±30% 以内。

## 7. レビュー & 公開フロー

1. CCO がドラフトを `site-moterist/03_content/<slug>/article.md` にコミット。
2. frontmatter の `publish_status: draft` のまま GitHub プッシュ。
3. CCO 自身の上記チェックリスト → クリアしたら `publish_status: review` に。
4. HUMAN がレビュー（コンプラ・トーン・URL）。
5. クリアしたら HUMAN が WordPress へ転載 → `publish_status: published` に。
6. [`TASK_BOARD.md`](./TASK_BOARD.md) の該当タスクを `[Done]` に移動し、公開 URL を併記。

## 8. アンチパターン（やったら差し戻し）

| アンチパターン | なぜダメか |
| --- | --- |
| CTA URL から `?source=moterist` を落とす | 流入元別 system addendum が効かず、CVR 計測も破綻する。 |
| 1 記事に CTA を 5 箇所散らす | 読者疲労 → 直帰率上昇。冒頭/中間/末尾の役割分担を尊重する。 |
| 作品ジャケットを Moterist 側でホストする | 権利侵害リスク。AdSense ポリシー違反リスク。 |
| 「失恋が治る」等の効能断定 | 景表法 / 薬機法に抵触する余地がある。 |
| Moterist の本文に成人向け要素を入れる | 教養媒体のトーンと AdSense / E-E-A-T を毀損する。成人向けへの接続は app.vodnavi.jp 側に閉じる。 |
| CTA セクションと「関連記事」を同じファーストビューに並列に置く | 視線の競合で両方のクリック率が落ちる。 |
